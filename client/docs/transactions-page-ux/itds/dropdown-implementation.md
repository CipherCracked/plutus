| ITD 1 - "Anchor dropdown menus with portals and absolute positioning, handle click-outside and Escape key." |  |
| :---- | :---- |
| **THE PROBLEM** | The `DropdownFilter` component currently renders its option list inline within the filter bar's DOM flow. When the dropdown opens, it pushes sibling filter controls down (layout shift). The dropdown closes on `onMouseLeave`, which fires as soon as the user moves the cursor from the trigger button to the options — making it nearly impossible to select anything. There is no click-outside handler, no Escape key handler, and no fixed positioning relative to the trigger. The question is: how to implement dropdown positioning and event handling so the menu is stable, dismissible, and doesn't disrupt the layout? | **OPTIONS CONSIDERED (Decision in bold)** |
| **Option 1** | **Portal + absolute positioning.** Render the dropdown via `createPortal` to `document.body` (outside the filter bar's DOM flow). Position the portal-rendered dropdown with `position: fixed` (or `absolute` with a `getBoundingClientRect` calculation) so it anchors to the trigger regardless of scroll container. Add a `useEffect` that listens for clicks outside the dropdown + trigger and Escape key, closing the menu on either. The trigger manages `open` state via `useState` + a `ref` to the trigger element. |
| **Option 2** | Inline `position: absolute` without portal. Keep the dropdown in the filter bar's DOM but set `position: absolute` relative to the trigger's parent. Close on `onMouseLeave` of a combined wrapper (trigger + dropdown) so the cursor can travel between them. |
| **Option 3** | Use a headless UI library (Radix, HeadlessUI) that provides `DropdownMenu` with built-in positioning, click-outside, and keyboard navigation. |
| **Option 4** | CSS-only hover/focus-within toggle — no JS state. Use `:hover` and `:focus-within` pseudo-classes to show/hide the dropdown. | **REASONING** |
| **Why portal + absolute positioning** | A portal renders the dropdown at `document.body` level, completely outside the filter bar's flex container. This eliminates layout shift — the dropdown floats above the page rather than pushing content down. Using `position: fixed` with coordinates calculated from `triggerRef.current.getBoundingClientRect()` anchors the dropdown to the trigger even when the filter bar is inside a scroll container. The click-outside + Escape pattern is the web standard for dismissible overlays — it gives the user a clear, predictable way to dismiss without relying on fragile `onMouseLeave`. |
| **Why not inline absolute** | Without a portal, the dropdown is still constrained by the nearest `overflow: hidden` ancestor (e.g., the scroll container or the card's `sharp-sm` class). The dropdown could be clipped. The `onMouseLeave` on a combined wrapper helps but is still fragile — if the user moves the mouse fast or the dropdown has rounded corners, the leave event can fire prematurely. |
| **Why not headless UI** | The assignment explicitly says "build a small internal component system" and the hand-built table rule suggests the user wants to see the implementation, not an abstraction. Adding Radix or HeadlessUI as a dependency for one dropdown pattern is over-engineering for a 5-endpoint app. The portal + ref pattern is ~50 lines of code and more transparent in review. |
| **Why not CSS-only** | CSS `:focus-within` is unreliable in Safari (inconsistent support for dismissing on blur). More importantly, CSS-only has no way to handle `document` click-outside — clicking anywhere outside won't close the dropdown. The user's complaint about weird behavior directly stems from this limitation. | **TRADEOFFS** |
| | | - The portal adds a DOM node outside the React tree's filter bar — this means Tailwind CSS classes still apply (global stylesheet) but scoped styles would not. The app uses global CSS, so this is fine. |
| | | - `position: fixed` requires calculating scroll offset — if the page scrolls while the dropdown is open, the dropdown must reposition. We handle this with a `scroll` event listener that repositions (or just close on scroll). |
| | | - Keyboard navigation (arrow keys, Enter, Space) is not included in the basic implementation. The dropdown closes on Escape and click-outside, but tabbing through options requires a separate enhancement. |
| | | - The click-outside handler must account for the checkbox inputs inside the dropdown being clicked — the event bubbles, so we use `event.composedPath()` or compare against the portal ref to determine if the click was inside. | **NOTES** |
| | | - Implementation: create a `useDropdown` hook that returns `{ isOpen, toggle, close, triggerRef, dropdownRef }` — reusable for all 3 DropdownFilter instances (category, status, payment method). |
| | | - `useEffect` for click-outside: `document.addEventListener('click', handleOutsideClick)` + `document.addEventListener('keydown', handleEscape)`. Clean up on unmount. |
| | | - Position calculation: `const rect = triggerRef.current.getBoundingClientRect(); dropdownRef.current.style.left = rect.left + 'px'; dropdownRef.current.style.top = rect.bottom + window.scrollY + 'px'`. |
| | | - Scroll handling: close the dropdown if the user scrolls the page (simplest correct behavior — avoids reposition calculation). |
