| ITD 2 - "Use CSS media queries with Tailwind breakpoint prefixes for responsive filter bar layout." |  |
| :---- | :---- |
| **The Problem** | The filter bar currently uses a single `flex flex-wrap gap-4` container for all 8 filter controls. At 2560px (desktop), this works — controls spread across the row with natural wrapping. At 360px (mobile), the flex-wrap creates a ragged multi-row stack where controls appear in arbitrary wrapping order, with no visual grouping or section labels. The assignment requires "responsive layout down to 360px wide" as an evaluation criterion for the hand-built table. The question is: how to make the filter bar adapt gracefully to narrow viewports while preserving scannability and the raw-aesthetics visual language. | **Options Considered (Decision In Bold)** |
| **Option 1** | **Mobile-first CSS with Tailwind breakpoints.** Use `grid` on desktop (3 columns: Search group, Filter group, Range group) with `md:` and `lg:` prefixes for wider breakpoints. On `sm` (640px) and below, stack groups vertically with a subtle section label above each. Use `gap` and `min-w-0` for proper truncation. No JS — pure CSS grid + flexbox. |
| **Option 2** | Collapsible filter sections. On mobile, each group (Search, Filter, Range) becomes an accordion — click to expand/collapse. The section header shows the group label and active count. |
| **Option 3** | Horizontal scroll bar on mobile. Wrap the entire filter bar in a `overflow-x-auto` container on mobile so controls scroll horizontally. Add visual indicators (faint gradient fade) to suggest scrolling. |
| **Option 4** | Popover-based filters on mobile. On screens <640px, collapse all filters into a single "Filter" button. Clicking opens a full-screen or centered popover with all controls laid out in a single column. The always-visible bar becomes just the button. | **Reasoning** |
| **Why mobile-first CSS with Tailwind breakpoints** | The filter bar has exactly 8 controls that fall into 3 natural groups (Search, Filter multi-select, Range inputs). On desktop, a 3-column grid keeps these groups visually distinct with sharp dividers — matching the raw-aesthetics principle of "grid-based layouts with clear column alignment." Tailwind's `grid-cols-3` + `md:grid` syntax makes this one class change. On mobile, stacking the groups vertically with section labels is the most scannable approach — each group is clearly delimited and the user can scan the labels. No accordion (Option 2) because 8 controls across 3 groups is only ~7-8 rows — not enough to justify the collapse interaction. No horizontal scroll (Option 3) because scroll-within-scroll is a poor mobile interaction, especially near the table's vertical scroll area. No popover (Option 4) because the user's stated requirement is "search merchant names as they type" — that needs to be immediately accessible, not behind a button. |
| **Why not collapsible sections** | Accordions add interaction depth (click to expand, click again to collapse). 8 controls in 3 groups is ~7 rows stacked — not enough height to justify collapsing. The "every element serves a purpose" principle means we should avoid hiding controls the user needs. |
| **Why not horizontal scroll** | Horizontal scrolling inside a vertically-scrolling table page creates a confusing scroll situation, especially with `overflow-y-auto` on the table container. Mobile users expect vertical flow. |
| **Why not popover** | A single "Filter" button on mobile means the user can't search merchants "as they type" without first opening the filter popover. This breaks the assignment's core requirement: "Search merchant names as they type." | **Tradeoffs** |
| | | - The grid-to-stack transition at the `sm` breakpoint (640px) means on tablets in portrait mode (~768px), the 3-column grid kicks in — this is fine and looks intentional. |
| | | - Section labels ("Search", "Filter", "Range") add a small amount of visual weight — but they serve the function of helping the user identify which group does what. |
| | | - On mobile, the stacked groups make the filter bar taller (3 section labels + 8 controls = ~11 rows). This is acceptable — the filter bar is at the top and the table scrolls below it. |
| | | - Tailwind's `sm:` breakpoint is 640px — the user's minimum is 360px. We should also add `xs:` (custom at 400px) for very narrow screens if needed, but `sm:` stacking handles 360px adequately. | **Notes** |
| | | - Breakpoint: `sm` = 640px. Below `sm`, the container is `grid-cols-1` (single column). Above `sm`, `md:grid-cols-3` (three columns). |
| | | - Each group gets a `div` wrapper with a `sm:block hidden` section label (only visible on mobile): `<span className="text-xs font-mono uppercase tracking-wider">Search</span>`. |
| | | - The always-visible "CLEAR" button moves to the right end of the bar on desktop, and to the bottom on mobile. |
| | | - `min-w-0` is critical on flex children inside the grid — prevents the merchant search input from overflowing its cell. |
| | | - The result count "X / 10,000 results" stays at the bottom-right on mobile, bottom-right on desktop. |
