| ITD 1 - "Use a unified focus-trap mechanism (focus trap on open, restore to triggering row on close, Escape dismissal, live-region announcements) for the TransactionDetail overlay on both mobile and desktop." |  |
| :---- | :---- |
| **THE PROBLEM** | The desktop TransactionDetail slide-over (`README.md` Not Done) lacks focus trap and `Escape` handling, while the mobile bottom-sheet/full-screen overlay already has both. Without a unified mechanism, keyboard users on desktop cannot dismiss the overlay or return to the table, and screen-reader users receive no announcement of overlay state changes. The virtualized table (`@tanstack/react-virtual`) only renders ~20 rows in the DOM, so focus restoration requires `scrollToIndex` to bring the triggering row back into the DOM before returning focus to it (`docs/table-performance-enhancement/itds/table-keyboard-navigation.md`). | **OPTIONS CONSIDERED (Decision in bold)** |
| **Option 1** | **Focus-trap library (`focus-trap` or native `tabbable` logic)** — trap focus within overlay on open; on `Escape` or backdrop click, call `scrollToIndex` for the triggering row index, then `focus()` the row button. Live region (`aria-live="polite"`) announces "Transaction detail opened" / "Transaction detail closed, focus returned to row N". Works identically on mobile (bottom-sheet) and desktop (slide-over); only the container component changes. |
| Option 2 | **Manual `Tab` interception** — intercept `Tab` events manually, track first/last focusable elements, and cycle focus. Same restoration logic. More code, same behavior, no dependency. |
| Option 3 | **No focus trap (current desktop state)** — overlay opens but focus stays on the page; user must click the close button to dismiss. Breaks keyboard contract and screen-reader expectations. | **REASONING** |
| **Frontend** | Option 1 provides the cleanest contract: a reusable hook or wrapper that takes the triggering row index, opens the overlay, and on close restores focus via `scrollToIndex`. The mobile overlay already uses this pattern (`docs/mobile-responsiveness/itds/mobile-overlay-implementation.md`); extending it to desktop closes the documented gap. Option 2 achieves the same result with more custom code and higher maintenance burden. Option 3 is the current broken state explicitly listed in `README.md`. |
| **Accessibility** | A live-region announcement is required for both viewports. Without it, screen-reader users don't know the overlay opened or that focus moved away from the table. The `focus-trap` approach ensures `Tab` cycles within the overlay, not into the background table, which matches WCAG 2.1 focus-order requirements. |
| **Desktop slide-over** | The desktop panel (`position: fixed` or `absolute` side panel) needs a backdrop element (`fixed` overlay behind it) that captures backdrop-click dismissal. This backdrop is invisible on desktop (low opacity) but must exist in the DOM to receive click events. The mobile bottom-sheet uses its own backdrop logic; the desktop version reuses the same interaction but with a different visual layer. | **TRADEOFFS** |
|  | Adding `focus-trap` (or equivalent logic) introduces a dependency (or custom implementation) solely for the overlay. At ~1KB, `focus-trap` is acceptable for the accessibility gain. The desktop slide-over must manage an invisible backdrop layer that doesn't interfere with table scrolling; this requires careful `z-index` and `pointer-events` coordination with the virtualized scroll container. |
| **NOTES** | - Focus restoration depends on `scrollToIndex` from `@tanstack/react-virtual`. If the triggering row scrolled out of view during overlay open, `scrollToIndex` must be called before `focus()` so the DOM node exists. <br>- The live region should announce only on open/close, not on every filter change, to avoid announcement fatigue. <br>- The desktop overlay does not receive swipe-down gesture (mobile-only); dismissal relies on `Escape`, backdrop click, or an explicit close button inside the panel. <br>- References: `docs/overlay-accessibility/intro.md`, `docs/table-performance-enhancement/itds/table-keyboard-navigation.md`, `docs/mobile-responsiveness/itds/mobile-overlay-implementation.md`. |
